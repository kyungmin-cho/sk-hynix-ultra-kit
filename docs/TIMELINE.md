# TIMELINE — 180분 운영표

> 시각은 전부 KST: `TZ=Asia/Seoul date +%H:%M%z` (끝이 `+0900`이 아니면 tzdata 없음 → `TZ=KST-9 date +%H:%M`).
> **화면 타이머 잔여 분이 1순위**, 시계 계산은 확인용. 둘이 5분 넘게 다르면 화면 값을 따르고 STATE에 차이를 적는다.

## 마감 계산

- T0 = 사람이 "과제 시작"을 누른 시각. 화면 값이 없을 때 **D = min(T0 + 180분, 13:20)**.
- 잔여 분을 알면(1순위): **D = 지금 + 화면 잔여 분**. 13:20으로 깎지 않는다. `bash <H>/scripts/init_state.sh --remaining-min <잔여 분>`이 STATE에 T0·D·체크포인트를 쓴다.
- 13:20 = 14:00 − 서술형 30분 − 대기 10분으로 잡은 **권장 마감 D′(하네스 해석, 공식 아님)**. 화면 기준 D가 13:20보다 늦으면 init_state가 경고하고 STATE의 D′ 칸에 표시한다 → 서술형 시작 시각을 사람이 화면·공지로 확인.
- 중간에 다시 맞출 때: hx-next에 "화면 잔여 m분"이라고 말하면 그 값으로 남은 시간을 센다.
- 4단계가 길어지면 5단계를 줄인다. **6단계(D−30~D)는 줄이지 않는다.**

## 운영표

| T+ | T0=10:00이면 | T0=10:40이면(D=13:20 상한) | 할 일 | 스킬·파일 | 끝 신호·체크 |
|---|---|---|---|---|---|
| 0~5 | 10:00~10:05 | 10:40~10:45 | clone·env_check·init_state·`codex` 실행(사람, README 첫 5분) → 첫 프롬프트 | README, hx-1-env | [ACTIVE] 3줄이 STATE에 |
| 5~15 | 10:05~10:15 | 10:45~10:55 | 과제 문서·데이터 프로파일 → TASK, 담당자 질문 3~5개 | hx-2-problem | **T+15**: TASK 한 문장, 질문 발송(사람) |
| 15~18 | 10:15~10:18 | 10:55~10:58 | 유형·모듈·의존성·서버·병렬 수 결정 | hx-3-capability | DECISIONS에 모듈·폴백 1줄씩 |
| 18~40 | 10:18~10:40 | 10:58~11:20 | **최소 E2E** 입력→출력 한 번 완주 + 검사 1개 | hx-3-capability, `run_and_log.sh`, `verdict.py` | **T+40**: 완주 여부, 토큰 점검 |
| 40~100 | 10:40~11:40 | 11:20~12:20 | 가설 1~2개 시행(`exp/<n>/`), 기준선 대비 숫자 | hx-4-trials | 채택/폐기가 숫자로 |
| 100 | 11:40 | 12:20 | "지금 제출해도 되나?" 실행 방법·검증 1개 확인 | hx-next | **T+100**: 토큰 점검 |
| 100~110 | 11:40~11:50 | 12:20~12:30 | 남은 시행 정리, 새 시행 멈춤 | hx-4-trials | |
| 110~D−30 | 11:50~12:30 | 12:30~12:50 | 채택안을 실행 경로 하나로, 검증 표, HANDOFF 초안 | hx-5-gather | 완료 조건 전부 PASS/FAIL/NOT_RUN 표기 |
| D−30~D−10 | 12:30~12:50 | 12:50~13:10 | **기능 동결.** 체크리스트·presubmit·verdict·HANDOFF·서술형 재료 | hx-6-final | **D−30**: 동결, 토큰 점검 |
| D−10~D | 12:50~13:00 | 13:10~13:20 | 사람이 화면 확인·경로 지정 커밋·**제출 시작**, 서술형 재료 2~3분 숙독 | hx-6-final | D 이전 제출 확정 |
| D 이후 | 13:00~ | 13:20~ | 대기 → 서술형(사람, AI·복붙 금지) | — | — |

- T0가 10:40보다 늦으면 D는 13:20에 고정되고 앞 단계부터 줄어든다. 줄이는 순서: 4단계 시행 수 → 5단계 → (6단계는 유지).

## 규칙

| 규칙 | 내용 |
|---|---|
| 40분 E2E | T+40까지 입력→출력 한 번 완주. 못 하면 범위를 줄여 지금 완주(`skills/hx-4-trials/references/rescue.md`) |
| 10분 전환 | 같은 문제로 10분 진전이 없으면 방향 전환. STATE 막힘 타이머 |
| 범위 축소 순서 | 화면 → 부가 기능 → 품질 케이스(정책만 문서화). 버리지 않는 것: 실행 가능성·핵심 판정+근거·검증 1개·실행 방법 |
| D−30 동결 | 새 기능 금지. Must·통합·문서·이해도만 |
| D−10 제출 | 사람이 제출을 시작. 에이전트는 형식 안내만 |
| 토큰 점검 | T+40·T+100·D−30에 사람이 `/status`·화면 표시 확인 → 빠르면 병렬 1 |
| 잔여 분 질문 | 체크포인트마다 hx-next가 사람에게 화면 잔여 분을 한 번 묻는다 |
