# 담당자 질문 틀

> **주의**: 담당자 메신저에 GitHub·MCP 같은 도구 이야기를 불필요하게 넣지 않는다(플랫폼이 경고문을 자동으로 붙인다는 보고가 있다, 미검증). 업무 언어로만 묻는다.
> 질문은 한 번에 3~5개, 각 한 줄. 사람이 직접 보낸다. 답은 `notes/TASK.md` §3과 `notes/DECISIONS.md` §0에 옮긴다.

## 다섯 칸 (빈 칸부터 묻는다)

| 칸 | 묻는 것 | 예 |
|---|---|---|
| normal | 정상은 어떻게 생겼나, 지금은 어떻게 처리하나 | "지금은 이 판정을 누가, 어떤 기준으로 하고 있나요?" |
| exception | 예외·결측·경계값은 어떻게 하나 | "값이 기준과 같으면 통과인가요, 불합격인가요?" |
| priority | 여러 조건이 부딪치면 무엇이 먼저인가 | "놓치는 것과 잘못 경보하는 것 중 무엇이 더 비싼가요?" |
| prohibited | 하면 안 되는 것, 쓰면 안 되는 데이터 | "결과에 넣으면 안 되는 정보나 쓰면 안 되는 컬럼이 있나요?" |
| success | 무엇이 되면 성공인가, 누가 결과를 보나 | "이 결과를 누가 보고 어떤 결정을 하나요? 몇 건 중 몇 건이면 쓸 만한가요?" |

## 잘 묻는 법

- 막연하게 묻지 않는다("무엇을 만들면 되나요?" ✗). 최근 사례 하나를 짚게 한다: "지난번 이런 일이 있었을 때 어떻게 했나요?"
- 수치를 받는다: 건수·허용 오차·처리 시간.
- 답이 없거나 늦으면 가정으로 진행하고 TASK §2에 "담당자 미확인"으로 적는다.

## 보낼 문장 형식

```text
[과제 이해 확인] 1) <정상/예외 질문> 2) <우선순위 질문> 3) <성공 기준 질문> — 답이 어려우면 제가 <가정>으로 진행하겠습니다.
```
