# 병렬 시행 — 방법·상한·격리·토큰

> 언제: 4단계에서 가설이 2개 이상일 때. 병렬은 선택이다. 기준선(n=0)이 없으면 병렬을 시작하지 않는다.

## 상한

- 동시 수 N = min(2, PAR_MAX, STATE `PAR_NOW`). PAR_MAX는 ENVIRONMENT.md R7 = min(상한, 유효 메모리 GB ÷ 3, NPROC − 1, PIDS ÷ 128).
- 시행마다 `OMP_NUM_THREADS` = `n_jobs` = max(1, NPROC // N). 메모리는 MEM_EFF_GB ÷ N 안에서(OOM은 구제되지 않는다).
- 3개 이상은 하지 않는다: 통합·검토 비용이 이득보다 크고 토큰 사용량이 평가에 간접 반영될 수 있다.

## 방법 (이 셋만)

| 방법 | 언제 | 하는 법 | 주의 |
|---|---|---|---|
| A. Codex 기본 서브에이전트 | 코드 수정이 필요한 가설 2개 | "가설 1은 exp/1/, 가설 2는 exp/2/에서 각각 서브에이전트로. 자기 폴더만 수정, 결과는 RESULT.md 4줄" | 승인 창이 뜨면 사람이 판단. 우회 옵션을 켜지 않는다 |
| B. 사람이 연 추가 터미널 탭 | 긴 작업을 따로 돌릴 때 | 사람이 IDE 터미널 탭을 하나 더 열어 `mkdir -p exp/<n> && cd exp/<n> && codex`(격리 폴더에서 대화형 실행) → 첫 문장은 `docs/PROMPTS.md` "병렬 탭 시작" | 워크스페이스 루트에서 띄우지 않는다. `notes/`는 메인 세션만 쓴다. 탭은 `exp/<n>/`만 |
| C. 파이썬 실험 스크립트 | 파라미터·모델만 바꾸는 비교 | `exp/<n>/run.py` 하나가 설정 목록을 돌며 지표를 CSV로 | 토큰이 가장 적다. 먼저 고려 |

- 쓰지 않는 것: 백그라운드 비대화형 Codex 여러 개(승인 대기에서 멈추거나 우회 플래그가 필요해짐), tmux 다중 에이전트, git worktree(`.git` 쓰기가 막힐 수 있음).

## 격리 규칙

- 시행 n은 `exp/<n>/`에만 쓴다: 코드·출력·`RESULT.md`. 제출 폴더와 `notes/`는 읽기만.
- 공통 입력 데이터는 읽기 전용으로 공유. 중간 산출물 경로에 n을 넣는다(`exp/2/out/…`).
- 실행은 `bash <H>/scripts/run_and_log.sh trial<n> -- <명령>`으로 → 로그가 섞이지 않는다.
- 같은 평가 구간·같은 지표·같은 seed로 비교한다. 다르면 비교가 아니다.
- 메인 세션이 결과를 모아 TRIALS(없으면 DECISIONS §2)에 적고 채택/폐기를 정한다.

## 토큰 예산·/status 체크포인트

| 시점 | 할 일 |
|---|---|
| T+40 | 사람이 화면·`/status`의 토큰 사용 표시를 본다. 남은 시간에 비해 빠르면 `PAR_NOW=1` |
| T+100 | 같은 확인. 병렬 중이면 1개를 정리하고 수합 준비 |
| D−30 | 병렬 종료. 새 시행 금지 |

- 줄일 때: STATE `PAR_NOW=1`과 토큰 점검 표에 한 줄(시각·사람 판단·PAR_NOW).
- 토큰을 아끼는 습관: 파일 통째 읽기 금지(`head`·`grep`·`sed -n`), 긴 출력은 로그로 보내고 끝 몇 줄만, 같은 설명 반복 금지.
