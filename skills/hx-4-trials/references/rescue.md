# 막힘·방향 전환·범위 축소·부분 제출

> 언제: 같은 문제로 10분 넘게 진전이 없을 때, T+40에 E2E가 안 됐을 때, T+100에 "지금 제출해도 되나"가 아니오일 때, 세션이 끊기거나 압축됐을 때.

## 10분 규칙

1. STATE "막힘 타이머 시작"에 시각을 적는다(hx-next가 센다).
2. 10분이 지나면 지금 방법을 멈추고 아래 표에서 하나를 고른다. 같은 방법을 세 번째 시도하지 않는다.
3. 결정을 DECISIONS §1에 한 줄(무엇을 버렸나·왜).

| 막힌 것 | 전환 |
|---|---|
| 패키지·설치 | 설치를 포기하고 stdlib 경로(templates의 폴백) |
| 서버·미리보기 | 사람이 IDE 터미널에서 실행 → 그래도 안 되면 정적 HTML 파일 (`skills/hx-3-capability/references/web-preview.md`) |
| 모델 성능 | 튜닝 중단, 기준선 + 규칙으로 제출하고 개선은 한계로 기록 |
| 데이터 이해 | 담당자에게 한 줄 질문을 보내고(사람), 가정으로 진행 → TASK §2 "담당자 미확인" |
| 큰 데이터·느림 | 샘플(`profile_data.py --sample`)로 먼저 완주, 전체는 마지막에 |
| 테스트 실패 원인 불명 | 입력을 1~3행으로 줄인 최소 재현 → 그래도 모르면 그 조건만 FAIL/NOT_RUN으로 남기고 진행 |
| Codex가 같은 실수 반복 | 새 지시로 짧게 다시: 파일 경로·기대 출력·금지 1줄. 긴 세션이면 HANDOFF 갱신 후 새 세션 |

## 범위 축소 순서

화면 → 부가 기능 → 품질 케이스 일부(정책만 문서화).

**버리지 않는 것**: 실행 가능성 · 핵심 판정 + 근거 출력 · 검증 기록 1개 · 실행 방법(README/HANDOFF §1).

## 부분 제출 전략 (시간이 모자랄 때)

- 언제든 "지금 제출 가능한 상태"를 하나 유지한다: 돌아가는 실행 명령 1개 + 출력 파일 + 검증 1행.
- 새 시도는 `exp/<n>/`에서 한다. 제출 경로는 채택이 확정될 때만 바꾼다.
- 못 한 부분은 숨기지 않는다: TASK §6 "하지 못한 것과 이유", HANDOFF §3 한계, 검증 표의 NOT_RUN.
- D−30 이후 새 기능 금지. D−10에 사람이 제출을 시작한다(그 전에 경로 지정 커밋을 제안).

## 세션 복원

- 컨텍스트 압축·새 세션 직후: `notes/STATE.md` → `<H>/AGENTS.md` → `notes/TASK.md` → `notes/HANDOFF.md` 순으로 읽고 hx-next로 다음 행동 1개만.
- 대화가 길어져(대략 90분 이상, 같은 설명 반복) 품질이 떨어지면: HANDOFF §2 현재 상태를 갱신하고 사람이 새 세션을 연다. 복원 문장은 `docs/PROMPTS.md`.
- 작업 환경 pause·재연결: 파일은 남는다. 서버·장시간 프로세스만 다시 띄운다(결과를 파일로 남겨 두었으니 재계산 최소). `run_and_log.sh` 로그에 `# end:` 줄이 없으면 그 실행은 중간에 죽은 것이다.

## BLOCKED (하네스 자체를 못 쓸 때)

ENVIRONMENT.md `STATUS: BLOCKED`이거나 하네스 스크립트가 안 돌면 `<H>/AGENTS.md` 맨 위 "하네스 없이 쓰는 4줄"만 첫 프롬프트로 보내고 진행한다.
