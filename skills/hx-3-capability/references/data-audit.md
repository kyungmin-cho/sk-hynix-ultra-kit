# 데이터 점검·정직한 평가

## 먼저 볼 것 (`python3 ${H:-/tmp/_harness}/scripts/profile_data.py <파일> --md`)

- 행 수·결측률·타입 혼합(숫자 컬럼에 문자)·중복 행·타임스탬프 후보·키 후보(고유값 = 행 수).
- 라벨 분포(불균형이면 정확도 대신 재현율·정밀도·비용).
- 값 노출은 최소로: 개인정보 의심 컬럼(출력의 `PII?` 줄)은 `--no-values`. 끝의 "담당자 질문 후보"는 초안 — 골라서 TASK §3에.
- 학습/평가(또는 주어진 train/test) 파일이 따로 있으면 둘 다 프로파일해 결측률·범위·라벨 비율·시각 범위를 나란히 비교한다(분포가 다르면 TASK §2 가정에).

## 분할 기준 (데이터 계약에 맞춰 하나 고르고 DECISIONS에 이유)

| 데이터 | 분할 | 금지 |
|---|---|---|
| 시간 순서가 있다 | 시간순(과거 학습 → 미래 평가) | 무작위 분할 |
| 같은 설비·로트·웨이퍼가 여러 행 | 그룹 단위(그룹이 양쪽에 걸치지 않게) | 행 단위 무작위 |
| 독립 표본·불균형 | 층화 분할 | — |

## 누수 점검

- 피처는 **시간 정렬 후 shift한 다음 rolling**(현재 행 값이 자기 피처에 들어가지 않게).
- 정제·스케일·임계값은 **학습 구간에서 fit, 평가 구간엔 apply만**.
- 라벨에서 파생된 컬럼·사후에만 알 수 있는 컬럼 제거. 점수가 "너무 좋으면" 누수부터 의심.
- 이상탐지 기준선은 **고정 구간**에서 계산(평가 구간이 기준선을 오염시키지 않게).

## 정직한 평가

- 기준선 먼저(다수 클래스·직전 값·단순 규칙). 개선은 기준선 대비 숫자로.
- 운영 조건 지표: 놓침 비용 vs 오경보 비용 → 임계값을 비용으로 고른다.
- 결과는 한 번의 평가 구간 숫자로 보고, 평가 구간에 맞춰 반복 튜닝하지 않는다.
- 평가에 쓴 명령·분할 방식·수치를 DECISIONS §2·§3에 남긴다.
