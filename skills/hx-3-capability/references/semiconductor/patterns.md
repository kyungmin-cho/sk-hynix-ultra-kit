# 반도체 데이터 형태와 분석 패턴

> 판정은 코드로(규칙·통계), 말은 해석만. 결과는 **조사 후보**로 보고하고 원인은 담당자가 확인한다.

## 해석 원칙 (먼저 지킬 것)

1. **통계 신호 ≠ 원인 판정.** 관리도 이탈·요인 편차는 "조사 후보"로 보고하고, 원인은 담당자가 확인한다고 쓴다.
2. **고정 기준선.** 관리 한계·정상 분포는 정해 둔 기준 구간에서 계산하고, 판정 대상 구간으로 다시 계산하지 않는다(순환 판정 방지).
3. **이상 = 후보.** 출력은 "어느 설비/로트/시점, 어떤 규칙, 근거 수치"까지. 확정 표현("불량 원인은 X") 금지.
4. 키 중복·결측은 조용히 버리지 않고 오류로 세서 보고한다.
5. 기준값과 같은 경계값 처리(이상/정상)는 담당자에게 묻고 코드 주석에 적는다.
6. 여러 요인·여러 센서를 한꺼번에 검정하면 우연히 걸리는 것이 생긴다(다중 비교). 상위 몇 개만 "후보"로, 표본 수와 함께.
7. 표본이 작으면(그룹당 수십 건 미만, 기대도수 5 미만) 순위만 보고 p값을 강조하지 않는다.

## 데이터 형태 → 먼저 할 일

| 형태 | 예 | 먼저 할 일 | 함정 |
|---|---|---|---|
| 센서 트레이스(long) | `time, eqp, chamber, sensor, value` | 장비·챔버·센서별로 나눠 시간 정렬 | 장비를 섞어 한 시계열로 보기 |
| 센서 요약(wide) | 웨이퍼당 행, 센서 요약값 수백 열 | 결측률·상수 열 정리(학습 구간에서 fit) | 전체 데이터로 정제 기준을 정해 누수 |
| 로트·웨이퍼 이력 | `lot, wafer, step, eqp, time` | 웨이퍼별 경로(어느 장비를 거쳤나) 표 | 같은 웨이퍼가 여러 행 → 행 단위 무작위 분할 |
| 수율·테스트 결과 | `lot, wafer, tested, passed` 또는 다이별 빈 | 키 중복·`passed > tested` 검사 후 집계 | 결측 웨이퍼를 0% 수율로 처리 |
| 이벤트·알람 로그 | `time, eqp, code, message` | 패턴 파싱 → 코드별·장비별 집계 | 같은 알람 반복을 별개 사건으로 세기 |
| 계측값 + 규격 | `value, lsl, usl` | 규격 이탈률과 관리도 둘 다 | 관리 한계와 규격 한계 혼동 |

## 분석 패턴 → 쓸 템플릿 (상세 절차는 `docs/PLAYBOOKS.md`)

| 질문 | 패턴 | 템플릿 |
|---|---|---|
| 이 센서가 언제 이상했나 | 직전 창 z·EWMA·CUSUM, 기준선 고정 | `templates/anomaly/stats_detect.py` |
| 담당자 규칙(연속 n회 초과 등)으로 판정 | 규칙 판정 + 근거 문자열 | `templates/anomaly/rules.py` |
| 공정이 관리 상태인가, 능력은 | I-MR·WE 규칙·Cpk (`spc.md`) | `templates/spc/spc.py` |
| 불량이 어느 장비·챔버·시간대에 몰렸나 | 공통성 분석: 요인별 불량률·카이제곱·순위 | `templates/yield_/groupstats.py` |
| PM 전후로 달라졌나 | 전후 구간 비교(같은 장비, 같은 길이 구간) | `templates/anomaly/`, `templates/spc/` |
| 불량을 미리 예측 | 시간·그룹 분할 + 누수 없는 피처 + 기준선 | `templates/ml/` |

## 보고 문장 형식

```text
[후보] <장비/챔버/로트> <기간>: <규칙 또는 지표> = <수치> (기준 구간 <구간>, 표본 n=<수>). 원인은 담당자 확인 필요.
```
